4.	 packs (id, name, created_date, user_id) - пачки измерений
 сейчас занят только id=1, новые записи начинать с id=2
5.	 parameter_types (id, name, unit_id) - справочник типов параметров
он уже заполнен, не изменять и не добавлять новые строки:

чтош, сгенерируй dml-скрипт (только insert и into) на чистом sql (ANSI-92, без специфичных конструкций) с тестовыми данными:
1. 3 новых пользователя (id=2,3,4), каждому position_id=1 и type_of_equipment_id=1
2. для каждого пользователя по 4 пачки измерений (id начиная с 2) с разными датами в 2026 году, имя пачки в формате ДДЧЧМ (например «24093» то есть 24 число, 09:30)
3. для каждой пачки по 5 строк в parameters (id начиная с 7), по одной на каждый параметр: parameter_type_id = 1 (высота), 2 (температура), 3 (давление), 4 (направление ветра), 5 (скорость ветра) и НЕ использовать parameter_type_id=6 (дальность сноса пуль), он не относится к ДМК
   значения в диапазонах:
   - высота метеопоста (type_id=1): целое число от -50 до 500, метры
   - температура воздуха (type_id=2): дробное число с одним знаком после запятой, от -58 до 58, градусы Цельсия
   - давление атмосферы (type_id=3): целое число от 500 до 900, мм рт. ст.
   - направление ветра (type_id=4): целое число от 0 до 59, два разряда 
     (например «05», «42»), деления угломера
   - скорость ветра (type_id=5): целое число от 0 до 15, м/с

и важно, специально включи несколько проблемных случаев для последующей проверки качества данных:
- одну пачку сделай полностью без параметров, то есть пустую, без строк в parameters
- в одной пачке сделай только 4 параметра из 5, пропусти один, например направление ветра
- одно значение температуры сделай вне диапазона, например 75.0
- одно значение давления сделай вне диапазона, например 950

выведи только готовый sql скрипт с комментариями, без лишних пояснений, используй сквозную нумерацию id без пропусков и дублей
